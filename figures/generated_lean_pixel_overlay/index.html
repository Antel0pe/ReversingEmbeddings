What the vector actually contains

lean vector = image(width, end lean) − image(width, start lean)

It contains one signed coverage change for each of the 784 pixels. These are changes in fixed pixel cells, not tracked objects moving between cells. The overall magnitude gives the amount of image change over this lean step. Dividing by end lean − start lean gives the average signed response per degree; a small step approximates a local derivative. The vector has no clock, so “speed” here means change per degree, not per second. Normalizing it to unit length removes its overall magnitude.

All frames come from the repository's Python renderer, sampled at 0.5° intervals. All five sampled widths are inside the default width range. This is a fixed-center, fixed-height slice, not a claim about the whole five-knob family. White slots with no color mean no drawn change; differences smaller than 0.0000001 coverage are omitted from color marks and support counts. Norms and inspected values include them.
